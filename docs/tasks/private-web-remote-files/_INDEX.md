# 子任务：文件数据面

**父任务：** [private-web-remote](../private-web-remote/_INDEX.md)  
**状态：** 第四阶段待执行；等待身份/租约与平台代理基础  
**范围：** `file-fabric` 与 `platform-agent` 的普通用户文件端点

## 工作包规则

下表 ID 在全项目唯一；预计为 2–4 小时主动工程工时，传输与等待另计墙钟。每包通过[统一验证入口](../../appendix/verification-strategy.md)运行同名场景；测试只操作带运行 ID 的隔离根，并校验目录外摘要不变。

执行按三个有界段恢复：`FF-A = FF-00 + FF-01 + FF-02a..FF-02c`（5 包，浏览器能力/SafeFS/变更检查点），`FF-B = FF-03a..FF-04b`（5 包，传输/复制检查点），`FF-C = FF-05a..FF-05d`（4 包，G4 检查点）。每段结束须更新 `_ACTIVE.md` 和签名证据索引。

## 完成定义

- G4 要求 `FF-00` 至 `FF-05d` 全部通过，覆盖 A08–A12；`FF-00` 失败即停止数据面实现并触发架构修改，每个目标包独立判定，不能用汇总成功率掩盖失败。
- 不存在跨设备移动、NAS 专用业务实现、任意地址复制或提权路径；真实 NAS 既有数据保持只读。
- 路径、传输、审计和部分成功各只有一个权威契约；平台适配只实现机制，不重写业务规则。
- 所有失败/取消场景均生成清理回执；隔离根外摘要发生变化即 G4 失败。
