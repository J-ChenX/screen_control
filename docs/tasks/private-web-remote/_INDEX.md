## 1. 目标与使用者

来源：**[用户确认]**。

- 产品仅供用户本人使用，把三台个人电脑统一到一个独立网页入口。
- 用户从任意一台授权电脑访问网页后，可以查看三台设备状态、控制另外两台电脑、浏览和管理三台设备的文件，并使用已有的 SyncClipboard。
- 三台电脑均支持真正的无人值守控屏：重启到系统登录界面后即可远程看到画面、输入系统密码并进入桌面，全程不需要现场点击授权，也不启用自动登录。

## 2. 固定设备与部署位置

设备范围、角色和部署位置来源于 **[用户确认]**；系统版本、地址、桌面会话、分辨率和在线状态等可变事实只在 [ENVIRONMENT_AUDIT.md](ENVIRONMENT_AUDIT.md) 维护。

| 设备 | 平台 | 角色 |
|---|---|---|
| `nix` | Ubuntu | 当前开发机、控制端、受控端 |
| `echova` | Ubuntu | 常驻服务端、控制端、受控端 |
| `jiang-chenx` | Windows | 控制端、受控端 |

- 常驻项目目录：`echova:${SCREEN_CONTROL_PROJECT_ROOT}`。
- 本地先开发与验证，再同步部署到 `echova`。
- 后续代理必须先阅读 [ENVIRONMENT_AUDIT.md §1.1](ENVIRONMENT_AUDIT.md) 的 SSH 连接手册，不猜测 Windows 用户名或把 `<windows-user>` 当作端口。

## 3. 全局工程原则

以下均为**[用户确认]**，约束后续架构、实现、迁移和审查。

- **G01 项目整洁：** 每项职责只保留一个权威实现及一处权威配置/文档入口。变更应修改、重构或替换原实现，不长期堆叠补丁、`new/v2` 副本或并行旧路径；迁移验证完成后主动删除失效代码、配置、脚本、依赖和文档。临时兼容路径必须写明用途与退出条件。本原则不授权删除用户数据、其他项目或必要的可回滚备份。
- **G02 现代且可持续：** 关键选型必须查阅选型当日的官方资料并比较适用候选，优先采用积极维护、安全记录良好、符合当前标准且适配三平台约束的成熟方案；不得仅因熟悉而采用停更、EOL 或已知不兼容技术。“先进”以维护状态、安全性、互操作性、性能、可升级性和实机验证为依据，不等同于盲目追新。
- **G03 可扩展与复用：** 优先复用可靠的现有能力；跨模块或跨设备重复且边界稳定的通用能力必须形成单一、可重复调用的工具契约，明确输入、输出、错误、权限、版本、测试和最小文档，调用方不得复制实现。具体载体可由架构选为库、CLI、服务 API、自动化命令或其他适合形式；一次性或尚未稳定的逻辑不为抽象而抽象。

## 4. 功能范围

### 4.1 统一网页

- **[已批准提案]** 首页展示三台设备的在线、离线、正在连接和异常状态。
- **[用户确认]** 每台设备提供控屏入口和统一文件入口；`echova:$HOME/nas` 只是 `echova` 文件树中的普通目录，不设置独立 NAS 页面、接口或权限模型。
- **[已批准提案]** 网页适配三台电脑上的现代桌面浏览器。
- **[用户确认]** 网页不提供远程终端、SSH 控制台或任意命令执行入口。

### 4.2 远程控屏

- **[用户确认]** 三台电脑均安装后台代理，并可互相作为控制端或被控端；被控端不需要现场点击授权。
- **[用户确认]** 只传输桌面画面以及键盘、鼠标输入，不采集、不编码、不传输系统音频。
- **[用户确认]** 发送端编码分辨率最高为 `1920×1080`：两台 `3840×2160` 设备输出 `1920×1080`，`nix` 的 `2880×1800` 按比例输出不超过 `1728×1080`。
- **[安全/工程基线]** 保持远端宽高比，不拉伸、不裁剪；浏览器缩放后鼠标坐标仍准确映射。
- **[已批准提案]** 首版按当前每台一块主屏验收；未来增加多显示器以及同时观看多个显示器不属于首版强制范围。
- **[用户确认]** 三台电脑的屏控代理均作为开机自启动的系统级服务运行；Ubuntu GDM 与 Windows 登录界面必须可见且接受键鼠，进入桌面后的锁屏也必须保持可控，不启用自动登录。
- **[用户确认]** `nix` 的首版远控基线使用 Xorg；当前配置与重启验证事实见 [ENVIRONMENT_AUDIT.md §2](ENVIRONMENT_AUDIT.md)。
- **[用户确认]** 普通结束远控、关闭网页、网络中断或异常断线均保持目标电脑当时的锁定/解锁状态，永不因此自动锁屏；远控界面提供“锁屏并退出”按钮，用户需要时主动锁定目标电脑并结束本次远控。
- **[安全/工程基线]** Windows UAC 等安全桌面的屏控能力与普通用户文件权限严格分离；登录前只要求屏控在线，文件功能在指定普通用户身份安全可用后再上线，并明确显示独立状态。
- **[安全/工程基线]** “锁屏并退出”只能调用目标系统的固定锁屏能力，不开放任意命令执行；无论锁屏返回 Confirmed、Failed 或 Unknown 都立即停止输入并结束本次控制通道。界面必须区分“锁屏成功并退出”“已退出但锁屏失败”和“已退出且锁屏结果未知”，不得把未确认的锁屏报告为成功；用户需要重试时重新建立会话。

### 4.3 统一文件管理

- **[用户确认]** 文件权限不区分当前电脑和另外两台电脑。入口从 Linux `/` 或 Windows 可用磁盘卷根开始，但只能列出和操作目标普通用户有权访问的对象；其他对象显示“权限不足”。文件模块不使用 Linux `root`、Windows `SYSTEM`、`sudo` 或 UAC 提权，系统级远控服务也不能把高权限传给文件模块。

| 权限域 | 开放位置 | 允许操作 | 主要限制 |
|---|---|---|---|
| 三台电脑统一文件入口 | Linux 从 `/` 开始；Windows 从可用磁盘卷根开始 | 浏览、上传、下载、创建文件夹、覆盖、重命名、复制、移动、删除；**[已批准提案]** 搜索、多选和批量操作 | 同一设备内可直接复制/移动；跨设备一次操作完成复制、无需人工下载再上传且不提供移动；禁止提权和特殊设备读写 |

- **[用户确认]** `$HOME/nas` 仍只在 `echova` 保存一份，但其浏览和操作完全复用统一文件入口；不做文件夹自动同步，不在其他电脑建立 NAS 镜像或长期缓存副本。
- **[安全/工程基线]** 同名目标不得静默覆盖；若目标在用户打开页面后已被其他程序修改，也必须重新确认。界面至少提供替换或取消，并可选自动改名保留两者；替换先完整写入临时文件，再校验提交。
- **[已批准提案]** 大文件采用流式、分块传输并显示进度；超过 3 GB 的上传、下载和跨设备复制支持断点续传。
- **[安全/工程基线]** 未完成上传不得以最终文件名出现；失败、中断或空间不足时，不得损坏现有文件，并能续传或安全清理临时数据。
- **[安全/工程基线]** 文件和非空目录删除均优先进入目标系统回收站（包括 `$HOME/nas`）；文件系统不支持回收站时，永久删除必须二次确认并明确标识不可恢复。网页不提供恢复、清空或自动清理入口。
- **[安全/工程基线]** 系统回收站目录不得出现在普通文件树中，也不能通过移动或路径构造绕过删除规则。
- **[安全/工程基线]** 符号链接、Windows junction/reparse point 和挂载点必须显示真实类型；路径规范化后仍执行普通用户权限和特殊设备限制，删除链接只删除链接本身，搜索和批量操作不得形成递归环。
- **[已批准提案]** 已挂载且普通用户可访问的本地、可移动、网络或云同步目录可以显示，但必须标出存储类型；对可能传播到外部服务的覆盖、移动和删除给出额外提示。

### 4.4 网络自动选路

- **[用户确认]** 三台电脑实际位于同一局域网且可直达时，屏幕和文件数据自动使用局域网；不在同一网络或局域网不可达时，自动切换到 Tailscale 的互联网直连或中继路径，不要求用户选择地址或模式。
- **[已批准提案]** 候选路径、身份与直连边界、自动重探测、防抖、状态展示和切换时限统一见 [NETWORK_ROUTING.md](NETWORK_ROUTING.md)；技术候选已由第二阶段比较，G0 与后续质量门负责实机验证。

### 4.5 SyncClipboard

- **[用户确认]** 复用现有 SyncClipboard；两台 Ubuntu 使用 `Super+V`（Win+V）打开原生历史面板，Windows 保留现有 Win+V 使用方式，网页不重复实现剪贴板历史列表。
- **[安全/工程基线]** Ubuntu 不依赖已知会在长时间运行后失效的应用内全局热键；由桌面环境持久绑定 `Super+V` 到 SyncClipboard 官方命令入口，并固定中文语言环境。登录、自启动、应用重启、锁屏恢复和长时间运行后均须保持可用，配置漂移必须被健康检查识别。
- **[已批准提案]** 网页分别显示“服务可达、实时文本同步、历史/文件同步”状态，不能用单一绿色状态掩盖部分失败。
- **[安全/工程基线]** 迁移到 Tailscale 私网入口并确认三台客户端可用后，才关闭公网 cpolar 入口和多余监听；禁用远控内核中会与 SyncClipboard 重复或形成循环的剪贴板通道。

## 5. 访问控制与安全边界

- **[用户确认]** 网页和内部服务不对公网开放，只允许三台登记的 Tailscale 设备访问；其他设备即使加入同一 Tailscale 私有网络也没有权限。
- **[安全/工程基线]** 授权同时绑定 Tailscale 节点身份与登记记录，不能只信 IP、设备名、Host 或转发头；设备替换必须人工重新登记，丢失设备可单独撤销且不得自动恢复权限。
- **[用户确认]** 网页采用单一强密码登录；服务器只保存抗暴力破解的密码哈希，不保存明文。
- **[用户确认]** 成功登录后的会话绝对有效期最长 7 天，到期必须重新输入密码。
- **[安全/工程基线]** 主动退出撤销当前会话；改密或撤销设备必须撤销相关网页会话、短期授权和活动控制/文件通道。7 天到期同样终止后续操作，长传输不得借机获得无限会话。
- **[安全/工程基线]** Cookie 使用 `HttpOnly`、`Secure`、`SameSite`；登录限速，所有写操作具备 CSRF 防护；所有网页、代理和实时通道均加密并校验目标、来源与源站。
- **[安全/工程基线]** 拒绝伪造设备、跨目标跳转、路径穿越，以及 Linux 设备节点/内核伪文件系统和 Windows 等价特殊对象；同一套服务端路径策略覆盖浏览、搜索、上传、下载、移动和删除。
- **[安全/工程基线]** 每台设备和每种用途使用独立、可轮换、可撤销的密钥或短期令牌；秘密存入操作系统安全存储或严格权限文件，不写入版本库、网页可见目录或日志。
- **[安全/工程基线]** 文件上传、下载、重命名、移动、替换和删除记录操作时间、来源设备、目标设备、权限域、动作和相对路径，但不记录文件内容或网页登录密码。

## 6. 可用性与运维

- **[用户确认]** `echova` 是唯一常驻网页入口；它离线时，另外两台即使在线也不能通过本网页互控或交换文件。
- **[用户确认]** 设备关机、仍在引导且屏控服务未就绪，或网络不可达时显示离线；到达系统登录界面且屏控服务就绪后自动上线。
- **[安全/工程基线]** `echova` 上的网页、反向代理、远控协调服务和 SyncClipboard 服务在主机启动后自动恢复；各设备的桌面/文件代理在其所需用户环境可用后自动连接，异常退出自动重启并显示分项状态。
- **[安全/工程基线]** 部署和升级必须有配置备份、版本锁定、健康检查与可回滚步骤；不能覆盖 `$HOME/nas` 现有数据。
- **[安全/工程基线]** 服务端磁盘不足、代理断线、上传中断、令牌失效或依赖异常时失败关闭，不误报成功；服务独立重启后不延长会话、不重放键鼠，文件可从已确认块续传。
- **[安全/工程基线]** 不影响 `echova` 上其他项目；已占用的 `8080` 端口不得复用。

## 7. 明确不在范围内

- **[安全/工程基线]** 麦克风、摄像头；Linux 设备节点/内核伪文件系统及 Windows 等价特殊对象。
- **[用户确认]** RAID、异机备份和磁盘故障恢复；`echova:$HOME/nas` 保持单一数据副本，系统回收站只能防误删，不能防磁盘损坏。
- **[已批准提案]** 首版不包含唤醒已关机、睡眠或休眠的设备；这些状态显示为离线。
- **[已批准提案]** 首版不包含多显示器同时观看和多用户并发控制。

## 8. 功能验收标准

以下 A01–A14 是随第一阶段批准的正式验收口径。

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A01 | 非授权设备访问 | 公网和其他 Tailscale 私有网络设备均无法建立有效网页或代理会话；伪造 IP、设备名、Host/Origin、转发头以及重登记后的旧身份均被拒绝 |
| A02 | 登录与 7 天会话 | 正确密码可登录；错误密码限速；第 7 天后强制重登；退出、改密、设备撤销和到期会终止对应会话与后续通道 |
| A03 | 重启与登录界面 | 三台电脑分别重启且无人现场操作；到达系统登录界面后屏控代理自动上线，可看到登录界面、输入系统密码并进入桌面，不启用自动登录 |
| A04 | 登录、锁屏与安全桌面 | Ubuntu GDM、Ubuntu 桌面锁屏、Windows 登录/锁屏及 UAC 安全桌面均能看到画面并接受键鼠；文件模块始终保持普通用户权限，未取得普通用户身份时显示离线 |
| A05 | 结束、断线与主动锁屏 | 分别从初始解锁和初始锁定状态测试普通结束、关闭标签页、切断网络及屏控服务异常，目标锁定状态均保持不变；“锁屏并退出”成功时目标确实锁屏且控制通道关闭，锁屏失败或结果未知时不得误报成功 |
| A06 | 画面约束 | 4K 设备发送不超过 `1920×1080`，`nix` 不超过 `1728×1080`；无音轨、无拉伸、指针映射准确 |
| A07 | 网络选路与正常控屏 | `nix`、`echova`、`jiang-chenx` 的 6 条有向来源→目标旅程均连续操作 10 分钟且无断线，并通过 [NETWORK_ROUTING.md](NETWORK_ROUTING.md) N01–N05；实际控屏通道 RTT 的 P95 不高于 150 ms、丢包不高于 1%，无原生统计时使用同端点心跳，不以独立 `tailscale ping` 冒充业务链路；外部网络限制只能由用户实际操作后明确接受降级 |
| A08 | 文件入口与安全边界 | 从三台来源均能进入三台目标的系统根/卷根；只列出和操作普通用户有权限的对象，保护路径明确返回权限不足；伪造设备、路径穿越、特殊设备及链接递归绕过均被拒绝 |
| A09 | 三机统一文件管理 | 从三台来源分别对三台目标普通用户可写的隔离目录验证上传、下载、创建文件夹、覆盖、改名、复制、移动和删除；三组设备对均执行双向跨设备直接复制，共覆盖 6 条源→目标路径且每条至少复制一个文件和一个目录，同时确认没有跨设备移动入口；`$HOME/nas` 使用相同入口，冲突不会静默覆盖 |
| A10 | 文件完整性与扩展操作 | 上传、下载和跨设备复制后哈希一致；跨目录/跨卷移动发生部分成功时准确报告，不伪装成原子操作；获批准的搜索、多选和批量操作全部通过 |
| A11 | 大文件与故障恢复 | 使用一个大于 3 GB 文件分别验证上传、下载和跨设备复制的断点续传、校验、原子提交，以及中断后无伪完整文件 |
| A12 | 回收站 | 文件及非空目录删除优先进入目标系统回收站；`$HOME/nas` 不例外。不支持回收站的永久删除必须二次确认，网页不提供恢复或清空入口 |
| A13 | 剪贴板 | 在 10 分钟观察窗内，每个系统依次发送 5 条文本、1 张图片和1个不超过 10 MB 的文件，其他两台均在 60 秒内收到；队列不得因连续失败停止。模拟短暂断线后 60 秒内恢复，网页分项状态与日志一致。两台 Ubuntu 分别在登录、自启动、应用重启、锁屏恢复及连续运行 24 小时后验证 `Super+V` 在 2 秒内打开中文历史面板 |
| A14 | 服务恢复与回滚 | 分别重启反向代理、协调服务、文件代理和桌面代理后，状态准确恢复且不延长会话或重放输入；配置备份可恢复；测试只操作隔离目录，测试目录外既有数据清单与校验摘要不变 |

## 9. 工程质量门

以下 QG01–QG03 是 G01–G03 的正式交付检查。

| 编号 | 通过条件 |
|---|---|
| QG01 | 每项能力有唯一责任归属；不存在未说明的重复实现、废弃入口、孤立配置、无用依赖或与实现冲突的文档；临时兼容均有理由和退出条件，迁移完成后旧路径已清理 |
| QG02 | 每项关键技术都有带日期和官方来源的选型记录，覆盖维护/支持状态、安全、候选比较、三平台适配、实机验证、锁定版本及升级或替换路径；未经用户批准不得采用 EOL 或停更依赖 |
| QG03 | 通用能力只有一个权威实现和稳定契约；出现两个以上实际调用方时复用同一工具，并以自动化测试覆盖权限边界、错误和版本行为，不存在复制实现 |

安全验收使用 SG01–SG06，权威定义与最早门见 [全局关注点 §8](../../appendix/global-concerns.md)。SG 覆盖 Origin/入口隔离、对象归属与 IDOR、bootstrap/秘密、文件审计一致性、敏感数据/证据和供应链/监听面；它们与 A/QG 同为交付门，不以功能正常代替安全通过。
