# SyncClipboard 非收藏历史保留规则

2026-09-22 已按用户要求增加 48 小时清理，保留原有数量限制。规则按创建时间计算，非收藏且严格超过 48 小时才清除；收藏保留，置顶未收藏不豁免。服务和客户端的定时清理约每分钟运行，离线设备在重新连接并完成同步后收敛，不保证关机期间执行。时间清理减少历史及附件积累，不等于进程内存立即按比例下降。

## 实现与验证

上游 SyncClipboard 3.1.5 开启历史同步时跳过客户端时间清理，服务端只有数量清理。因此不能只将客户端界面里的保留天数改为两天：本次补齐服务端清理，并让客户端原有任务继续处理本机独有记录。同步历史沿用原有通知和删除版本，不直接修改生产数据库、不新增常驻服务或更改监听地址。

源码补丁、精确工具链和操作说明见 [部署入口](../../deploy/g0/suite/syncclipboard-retention/README.md)。验证情况：

- 服务端及 Linux/Windows 客户端核心程序集构建通过，使用 .NET SDK 8.0.419 和 v3.1.5 精确提交，未升级依赖。
- SQLite 隔离测试通过：48 小时边界、收藏与附件保护、置顶清理、其他用户隔离、删除版本、离线增量查询、收藏更新、幂等和 100 条分批。
- 客户端隔离测试通过：开启历史同步时清理过期 LocalOnly，保留收藏、近期记录以及由服务端负责的 Synced 记录。
- 用当前安装依赖和新服务端程序集启动隔离服务，鉴权接口正常，定时任务自动清除合成旧记录、保留合成收藏记录。首轮因测试夹具缺少迁移版本记录失败，补齐夹具元数据后通过；生产无数据库结构迁移。
- 部署后 echova、nix、Jiang_ChenX 的客户端均恢复单实例；三端所用版本、当前剪贴板和历史查询接口返回 HTTP 200。服务端启动初期曾短暂返回 502，启动完成后复查通过。Windows 仍在原用户交互会话，临时重启任务已删除。

## 备份与回滚

服务端在停止状态备份数据库、附件和程序集，备份位于 `$HOME/.local/state/screen-control/retention-20260922-234506/`；执行其中 `rollback.sh` 可恢复原程序集、撤销新增保留配置并重启服务。两台 Linux 客户端备份位于 `$HOME/.local/state/screen-control/client-retention-20260922-234852/`，包含原程序集、配置、数据库和历史附件，`rollback.sh` 恢复代码与配置。Windows 对应备份位于 `%LOCALAPPDATA%\ScreenControl\client-retention-20260922-234946\`，`rollback.ps1` 恢复代码、配置及交互会话；脚本已做语法检查。

上述脚本只回滚代码和配置，**不会自动撤销已同步的历史删除**。数据恢复需要协调各端同步与删除版本后从备份恢复，禁止在线直接覆盖旧数据库。备份含用户数据，不进入仓库，也不自动清理。

第三方软件升级可能覆盖本次程序集，升级前须按固定补丁重新构建、验证和部署。原有 GC、原生分配器与服务组内存限制继续保留。
