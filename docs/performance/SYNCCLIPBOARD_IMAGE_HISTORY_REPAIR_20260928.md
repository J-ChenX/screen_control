# 2026-09-28 图片采集与重复复制历史修复

## 已确认的原因

本机 echova、nix、lerrem 的已部署 `SyncClipboard.Core.dll` 相同，引用 `Magick.NET-Q16-x64`；三台安装包仅提供 `Magick.NET-Q16-AnyCPU`。本机和 nix 有对应程序集加载失败日志；lerrem 虽未发现同样的历史错误日志，但相同程序集与缺失依赖确认它也受影响。使用实际安装宿主直接调用旧核心的图片解析方法，可复现 `FileNotFoundException`。PixPin 在隔离 X11 中点击复制，另一进程可读取 401×251 PNG，复制端正常。

用户报告的地址文本在三台数据库中均存在，但标记为已删除：首次创建为 9 月 22 日，最近复制为 9 月 28 日 15:58:33，服务端于 15:58:47 再次删除。旧清理补丁按首次创建时间计算，重复复制仅更新最近使用时间，导致刚复制的旧内容再次被清理。系统当前剪贴板与历史删除互不等同，因此仍能粘贴。本机历史还按首次创建时间排序，重复复制的旧条目即使恢复也不会排到前面。

## 修复与部署

- 三台 Linux 客户端统一用 `Platform=AnyCPU` 构建的核心程序集，匹配实际安装图像依赖。保留原通知连接恢复、48 小时配置、内存设置、同步账号与历史数据库。
- 客户端本地独有历史与服务端同步历史均要求“创建时间与最近复制／使用时间都超过 48 小时”才过期。收藏仍受保护，置顶不豁免，数量上限不变；单纯更新其他元数据不会刷新保留期。
- 三台既有历史面板设置 `HistoryWindow.SortByLastAccessed=true`，其他窗口偏好不变。
- 用服务端既有带版本通知的历史更新 API 恢复用户报告的那一条已删除文本，并刷新最近使用时间；没有批量恢复过期历史，也没有直接改写在线数据库。
- 部署脚本增加强制前置验证：使用目标已安装宿主、依赖清单、托管与原生库执行 PNG 解码与重新编码；验证失败时不停止客户端。启动失败恢复代码与配置。
- 本次只更新剪贴板服务端与三台客户端，没有部署控屏项目中其他尚未提交的前端或 MeshAgent 修改。

- 使用保留规则锁文件指定的 SyncClipboard v3.1.5 源码和 .NET SDK 8.0.419，保留补丁与通知恢复补丁共同构建。
- 三台实际安装宿主的图像依赖、合成 PNG 解码和重新编码均通过；旧错误 DLL 的负测按预期被拒绝。
- 独立 Xvfb、隔离配置和合成图片，通过跨进程 X11 读取、实际 Avalonia ClipboardFactory 解析、图片缓存及历史数据库入库。探针首次在窗口初始化前读取超时，改为等待窗口就绪后通过；该调整仅在测试探针中。
- 服务端与客户端保留规则回归通过：旧内容删除后重新复制恢复、最近使用的 48 小时边界、收藏保护、元数据更新不延长保留期、分批清理、删除通知查询和本地独有记录清理。
