# Screen Control 源码复查与防复发验证

日期：2026-09-28。范围：浏览器图块处理、连接结束与重连、Go 会话/中继/指标缓存、已装 Linux MeshAgent 与上游回收修复。

## 结论

本次“图像解码失败或积压超过预算就结束会话”的应用处理路径已移除并实机验证。持续运行 11 天后增长到约 11 GB 的原生代理问题尚未复现或完成根治验收，不能承诺永不复发。

## 已修复并部署

1. `web/src/features/desktop/memory.ts`：逐块解码、绘制后立即关闭位图；使用高低水位暂停/恢复采集。突发积压清理后请求完整画面，保持同一连接；解码/绘制异常同样自动恢复。旧解码结果按代次隔离，结束时取消恢复定时器、清空队列和画布。
2. 审查发现单张合法大图可能因 16 MiB 积压阈值被反复拒绝。改为单张独占处理，仍遵循 64 MiB 中继消息上限；预算限制积压，不将单张合法大图误当作积压。
3. 审查发现任务排入微任务后立即断线仍会进入解码器。新增解码前失效检查，停止无用途的新解码工作，迟到位图仍立即释放。
4. 新增 `tests/performance/desktop-recovery.mjs`：只在测试浏览器注入故障，不发送远端键鼠、不保存屏幕、不锁屏；断言真实画面恢复且会话未重建。

部署版本：`20260928T032658Z-desktop-lifecycle`。仅更新门户静态资源并原子切换 current，未重启服务、未替换代理。上一版 `20260928T031226Z-desktop-recovery` 与原始 `20260922-memory` 均保留。新版本目录中的 `rollback-source.txt` 记录直接回滚目标。

## 验证结果

- 前端 66 项测试全部通过；类型检查、生产构建、差异检查通过。
- 连续 2,000 张图块测试：最多同时保留一张位图，每批绘制后位图计数归零，序号重置后继续工作。
- 高低水位、解码失败、迟到结果、尺寸切换序号缺口、断线取消定时器、合法大压缩图等回归通过。
- `mise exec -- go test -race ./internal/g0bridge` 通过。
- 部署后的真实控屏故障测试：12 轮交替注入解码失败和 1,000 图块突发积压；只创建一次会话，测试期间未调用结束接口，12 次刷新后真实画面恢复；最多同时 1 个解码/1 张位图，最终位图数为零；实际桌面 2880×1800，协议状态仍为已连接。
- HTTP 页面、新静态资源和健康 API 检查通过。

实机测试目标为 nix，不代表 Windows、手机真机或所有分辨率均已验收。

## 其他源码审查结果

- Go 中继每方向使用固定 32 KiB 缓冲，经写端背压限制读端，未发现把历史画面无限累计在门户内存的实现。
- 会话正常结束、握手失败、过期和中继退出均有删除、停止计时器、取消上下文和归还配额路径；相关包竞态测试通过。
- 指标缓存按设备覆盖，采样单任务有 3 秒期限，连接结束立即关闭；没有发现把每次采样追加到无限历史数组的路径。
- 上述属于限定范围审查和回归结果，不等同于全系统无泄漏证明。

## 仍需处理的原生代理风险

两台已装 Linux 代理的 `-info` 均显示旧提交 `62b206e0b485b296e8a73a6547cef02bbf5a2d62`，2026-02-15 构建，早于以下修复：

- [MeshAgent #406](https://github.com/Ylianst/MeshAgent/pull/406)：连接取消遗留 WebSocket 状态、请求、SNI 和分片缓冲的回收；避免重复重连调度。
- [MeshAgent #415](https://github.com/Ylianst/MeshAgent/pull/415)：子进程退出后的对象回收、按脚本堆增量触发 GC，以及 Linux/glibc 归还空闲页。

已在隔离目录将两个补丁回移到原版本并成功编译 Linux x64；保留了针对旧平台条件的适配。旧版与候选各完成 30 次固定子进程启动/退出冒烟测试，均正常退出，RSS 峰值分别约 7.69 MiB、7.60 MiB。此工作量没有复现 GB 级增长，不能据此宣称候选修复有效；尚未验证真实代理身份、取消/重连、控屏全流程和 Windows 工件，因此候选没有部署。较大规模探针在原时限内未完成，后续需修订测试负载和时长，不能记为压力测试通过。

远端仓库 `deploy/g0/meshagent/native-memory/` 保存可复现补丁、来源和摘要清单。原生修复必须在隔离环境通过上述验证后再发布，并跟踪回收后基线及增长斜率。现有系统硬上限仍是兜底保护，不能作为长期增长已修复的证据。

## 实际保证范围

已通过测试约束已知浏览器回归：预算压力不会进入原来的主动结束会话路径，无效队列与位图会被清理。网络故障、浏览器自身资源不足和第三方代理故障仍可能影响连接；原生长期增长风险尚未关闭。长期验收应覆盖空闲、反复连接、持续控屏、慢客户端和恢复后的内存基线，不能用重启后低内存替代。
