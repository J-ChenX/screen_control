最终 `Release|x64` 服务工件 SHA-256 为 `27a434c99ac6d7e30f6aca6750c91eafe72265e18fa8ce91fd7892ba61ef44cf`，Rust MSVC 静态库为 `50b0046453fe860670b3656ba7c247fef1f62f66c301ca87930783b477c37db8`。MSBuild `17.13.19.12613` 对两个工程重建成功；传输包在远端核对摘要后使用。源码、补丁、库、构建日志和最终工件的关联见[本轮清单](../../deploy/g0/meshagent/rust-native/windows-runtime-manifest.json)。清单是本轮来源记录，不替代完整发布 SBOM。

## Rust 分配改进

`Decoder::feed` 原先在最后分片需要扩容时仍执行倍增。消息随后立即完成并移交输出，额外预留没有后续增长用途。现在仅在这一分支按完整消息长度申请容量，中间分片保持预算内倍增，没有额外缩容拷贝或协议变化。

独立正常输入程序对比 HEAD 与当前实现：10,000 + 最后 3 字节的输出 `Vec` 容量为 **20,000 → 10,003 字节**，减少 9,997 字节；输出内容一致，连接销毁后输出仍有效，两版消息完成后的连接保留容量均为零。若第二块不是最后分片，两版容量均为 20,000；最后分片无需扩容时行为也不变。此收益是局部分配容量，不能推算为进程 RSS 或系统峰值降幅。

`4213e8dd3186061f2fe077edb5563d6f37c22a1b8bf54a47c12064b08ddf7039` 包含五个可选 C 生命周期补丁，Rust 静态库为 `db297a…e7e7a`。它曾完成首轮六次及追加 18 次正常会话、暂停/恢复和普通结束，但随后保留后的新会话超时。以下数据仅属于该已撤回组合，不能混入最终工件结果。

### 一组六轮对照

使用 `windows-agent-memory.py` 同时记录同路径代理进程；每组 24 样本、约 81 秒，设定间隔三秒另加采集耗时。每组工件摘要及主 PID 固定，末尾 12 样本均无采集子进程。两版均从刚启动的服务开始，但运行顺序和桌面内容未严格控制。

| 私有提交量（MiB） | 旧版 | Rust 组合 |
| --- | ---: | ---: |
| 首样本 | 41.21 | 53.16 |
| 同路径进程采样峰值 | 115.36 | 95.16 |
| 末样本 | 46.09 | 58.09 |
| 主进程采样峰值 | 49.46 | 61.61 |
| 采集子进程采样峰值 | 66.42 | 34.54 |

新版主进程首、末值均约高 12 MiB；两版首末增长均约 4.9 MiB。该组采样峰值下降不能表述为整体驻留降低，更不能证明修复了长期泄漏。Working Set 求和会重复计入共享页，因此本表使用 Private Bytes；三秒轮询并非真实峰值测量。

追加 18 轮的 50 样本中，采样峰值为 126.81 MiB，结束后主进程约 57.64 MiB，末段采集子进程已退出。这个更高峰值进一步说明不能承诺固定降幅。Rust 消息结束即移交/释放分片容量的机制及本轮正常会话已生效，整体内存收益仍需重复受控对照和长期记录。

在修正“绘制成功后才计数”的探针上再次通过暂停/恢复及输入链路检查；之后连续十个空闲样本均只有同一主进程，私有提交量 57.64 MiB、506 个句柄、9 个线程，工件摘要一致。一度保留后，自动恢复入口正确返回 `already-retained`，服务及摘要健康；但随后的普通会话未在 30 秒内建立连接，不能以服务健康代替会话可用。显式恢复原 EXE/guard 后，相同入口的六轮会话全部通过。该组合已撤回，具体根因未确定；不能把缩小补丁集合后的通过当作定位了某个具体补丁。

## 操作与限制

`windows-canary.ps1 Arm` 在替换前备份旧 EXE、guard 和身份文件，并设置六分钟 SYSTEM 自动回滚。`Retain` 仅在操作者完成实机验证后显式调用：核对运行摘要、构建清单、备份及守护，原子写入保留凭据后撤销定时回滚。提交前始终保留自动回滚；排队的自动任务在同一互斥锁内复查凭据。`Restore` 随时显式恢复旧 EXE/guard。

回滚保留当前 `MeshAgent.msh/db`，不会自动把有效身份数据库倒退到旧快照。本轮没有数据库模式迁移，且已通过恢复旧版后的实际会话；身份备份只用于人工恢复。隔离 PowerShell 测试覆盖保留凭据写入失败、任务注销失败、自动恢复先完成、保留先完成及显式恢复，未调用真实服务或任务。

本轮最多进入 Windows 可回滚运行观察，未宣布 G3、全平台发布或长期验收。Linux Rust 接入、完整输入语义/画质验收、完整 SBOM、同负载长期驻留和既有约 11 天故障窗口仍未完成。出现会话失败、主进程重启、采集子进程不退出或空闲内存/句柄持续增长时，恢复旧版并保留对应版本证据。

复查入口为 `tests/performance/windows-agent-memory.py`、`desktop-memory.mjs` 和 `desktop-session-live.mjs`；最后一个现在发送一次 Ctrl 按下/释放，不能混入默认被动测试。可信门户和 SSH 目标只从当前私有配置读取。构建和保留命令见[部署说明](../../deploy/g0/meshagent/rust-native/README.md)。
