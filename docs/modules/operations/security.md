# Operations — 安全

**最后更新：** 2026-09-03

## 秘密与供应链

| 资产 | 存储/权限 | 轮换与恢复 |
|---|---|---|
| TLS/LocalAPI 访问 | edge 专用宿主权限 | 证书自动更新；权限漂移 fail-closed |
| 网页/代理凭据 | OS 凭据存储或 0600 文件，按设备/用途分离 | 轮换增加撤销代次 |
| 在线 SQLite/配置 | 独立服务 UID、目录 `0700`/文件 `0600` 或等价 ACL，位于主机加密卷；禁止其他容器挂载 | 恢复/宿主密钥变化后撤销旧会话/能力 |
| SQLite/配置备份 | 应用层加密、echova 专用备份身份，与在线卷密钥分离 | 恢复后增加恢复代次并验证旧对象失效 |
| Mesh 数据卷 | 单独加密备份和访问控制 | 恢复后轮换 Mesh/Agent 关联凭据 |
| SyncClipboard 数据/逐设备凭据 | 服务数据属专用身份；客户端私钥在各机 OS 凭据存储且不可导出 | 逐设备轮换；替换/丢失立即撤销对应 serial，不轮换成共享密码 |
| 构建产物 | digest/hash 固定，生成 SBOM | 金丝雀后推广；未知 hash 拒绝部署 |

- 禁止把秘密写入 Git、Compose 环境字面量、镜像层、进程参数、URL、日志和证据索引。
- 构建依赖使用锁文件/校验和与固定镜像 digest；Go 生产/CI 版本、Node/React、SQLite、Tailscale、Mesh、SyncClipboard 均对照技术评估。
- 验收工具无任意命令网页入口；只能由本机运维执行允许列表场景，并使用明确隔离目录。

## 数据与证据生命周期

保护等级和默认处置遵循[项目威胁模型的数据分类](../../appendix/threat-model.md)：

- 身份在线库、登记表、密码散列、会话/能力摘要、审计路径及操作摘要均为 `R2 敏感元数据`；除加密卷与最小目录权限外，SQLite 临时文件、WAL、共享内存、备份和崩溃转储必须继承同级保护。运行前断言目录所有者/模式/卷加密；不满足则数据库不打开。
- 文件审计库可以保存完成追责所需的规范化相对路径，但不得写绝对 home 路径、正文、查询串或能力。导出的验收证据默认只保留对象类型、结果、时间和相对路径的带项目密钥 HMAC；确需明文相对路径时，证据升级为 `R2`、记录理由和销毁日。
- 屏幕帧、文件传输正文、键盘输入和凭据为 `R3 内容/秘密`，只存在于完成当前传输所需的内存；SyncClipboard 正文是唯一业务持久化例外，只能存在于其加密用户数据库/历史/队列及同保护等级备份，并遵循用户配置的保留/清理周期。所有 R3 均不得写应用日志、指标、普通 trace、swap、core dump 或常规验收证据。输入日志只允许序号、设备、结果和时间，禁止键值/文本；断线/撤销时清空输入队列且绝不重放。
- 测试录屏默认禁止。只有操作者显式开启、使用合成账号/合成内容且画面有持续录制标识时才允许生成；产物以独立密钥加密，清单记录 owner/purpose/createdAt/destroyAt，默认 7 天销毁。出现真实密码、私有文件或个人剪贴板内容时立即停止、隔离并销毁，不能作为验收附件。
- 普通结构化测试证据默认保留 30 天；安全审计保留 180 天；到期任务以清单中的内容地址精确删除并产生无敏感内容的销毁回执。法律/故障保留必须由本地运维明确延长并记录新销毁日。发布前执行日志、trace、core、浏览器产物和证据目录的敏感模式扫描。

## 特权与网络装配

- 只有两个 echova 接入边界可直接读取 LocalAPI，且各用独立 OS 身份/ACL：`edge-gateway` 仅为 Portal/Desktop 浏览器 socket 调用 `WhoIsForIP/GetCertificate`；`clipboard-gateway` 仅为它实际接受的 SyncClipboard mTLS socket 调用 `WhoIsForIP`，不能访问证书、路由或替其他进程查询。端点 `screen-control-agent` 不获 LocalAPI 权限；最小权限 `screen-control-peer-helper` 以独立系统身份只为它自行接受的专用文件连接调用 `WhoIsForIP`。三者服务定义、LocalAPI ACL、监听与可执行 hash 均进入 release manifest，任一越权方法/任意 IP 查询测试失败即停止服务。
- Portal 与 Mesh 分配不同证书名/Origin；部署检查拒绝共享 host 的路径路由。网关到 Mesh 的 allowlist 明确删除 Cookie、Authorization、CSRF、Forwarded/X-Forwarded 和项目身份头，并把 Mesh `Set-Cookie` 视为上游安全故障。响应头、WS upgrade 和错误路径均做端到端断言。
- bootstrap/登记工具只安装给受限本地运维 OS 身份，无远程网页或 SSH 批处理入口；秘密输入只走关闭回显的本地 TTY 或专用文件描述符。服务安装完成但 bootstrap 未完成时，公网、Tailnet 和本机非运维调用方都不能创建首个身份。

## 破坏性操作保护

部署前记录测试根并解析真实路径；拒绝 `/`、用户 home、`/home/operator/nas` 根和工作区根作为清理目标。既有数据只生成只读清单/摘要；删除仅针对带本项目测试标记的隔离对象或满足迁移退出条件的明确配置。

## 安全门

- A14：逐组件重启/回滚、会话不延长、输入不重放、隔离目录外摘要不变。
- QG01：扫描重复入口、孤立配置、无用依赖和过时文档。
- QG02：官方来源、维护状态、版本锁、SBOM、三机兼容和替换路径完整。
- 恢复演练或敏感日志扫描失败时，发布失败关闭。
- 发布安全门还必须通过：在线数据库权限/卷加密断言、证据到期销毁演练、core/swap 策略检查、peer helper ACL 与 LocalAPI 故障注入、两个 Origin 分离和 Mesh 头剥离/`Set-Cookie` 拒绝测试。

集中威胁、控制所有者、验证证据和残余风险接受条件见[项目威胁模型](../../appendix/threat-model.md)。
